# ZeroCode 同类产品 MVP 架构

输入为 [调研报告](recon.md) 和 [功能矩阵](features.csv)。S、F 编号沿用调研。模型计费公式、限流语义、密钥生命周期和兑换规则是本方案的产品决策。原站的实际扣费和兑换行为尚未实测。

## MVP 范围

首发闭环为登录 → 查看模型与价格 → 创建分组密钥 → 调用单一上游的文本模型 → 按用量扣费 → 在仪表盘对账 → 用内部兑换码补额。首发面向受邀试点账号，支持标准客户端的非流式文本请求。

| 流程 | 首发范围与取舍 |
| --- | --- |
| F01 选型和接入 | S03、S04、S14。模型目录、当前分组价、显示自有接入地址、签发密钥、停用/恢复/撤销、累计额度与每分钟请求上限。先支持单一上游、一个文本模型及一种接口。 |
| F02 用量与费用 | S01、S05。余额和可用额、启用密钥数、今日/累计请求、Token 和费用、按密钥/日期筛选、游标分页、日粒度曲线。 |
| F03 补额 | S08。用内部签发的一次性码增额并查钱包流水。矩阵列为必做的 S02 外部卡网购买延后，在线支付和支付回调后续单独设计。 |
| F04 订阅和订单 | S06、S07 延后。调研中仅验证空态，首发交付账户钱包流水。 |

S12 提供受邀用户登录。平台监控、代理、资料管理、CCS 导入、自定义密钥、IP 白名单、到期策略、流式输出、工具调用、多模态和多协议接入进入后续阶段。首发兼容范围需写进接入说明，部分依赖 SSE 或 Responses API 的客户端不在首发支持范围。

## 技术栈

| 层 | 选择 | 原因 |
| --- | --- | --- |
| Web 与 API | Next.js App Router + TypeScript，Node.js Runtime，Tailwind CSS | 用同一个部署单元提供控制台、管理 API 和模型网关，路由处理器直接接收 HTTP 请求。 |
| 登录 | Supabase Auth，受邀账号用邮箱和密码，服务端验证会话 | 复用会话与账户管理，控制台和网关各自鉴权。 |
| 数据库 | Supabase 托管 PostgreSQL + `pg`，手写 SQL 迁移 | 余额、限额、兑换码、流水和用量都在同一数据库事务边界内。 |
| 校验 | Zod，显式校验管理请求和模型请求 | 约束金额、页大小、文本请求体和上游响应字段。 |
| 上游 | 配置一个官方 OpenAI API 适配器或本地桩，环境变量提供项目自有密钥 | 先用桩稳定验证账本，再切换官方上游。模型、上下文大小和用途以自有账号可用范围为准。 |
| 运行与任务 | 单个常驻 Node 容器，与数据库同区域。部署平台每 5 分钟调度同一镜像中的对账命令 | HTTP 超时可以明确设置，扫描待处理请求不占用 HTTP 处理时长。多个副本仍共享数据库锁。 |
| 运营 | 内部受控 CLI 签发试点兑换码，结构化日志和请求 ID | 无需运营后台和支付供应商。日志可用请求 ID 对账。 |

候选方案还有独立网关服务和控制台服务。首发采用单应用，可在代码内将鉴权、上游适配、账本和查询分成模块。如果 HTTP 并发或流式连接占用成为瓶颈，再拆部署。

技术依据：[Next.js 路由处理器](https://nextjs.org/docs/app/getting-started/route-handlers)、[Supabase 服务端会话](https://supabase.com/docs/guides/auth/server-side/nextjs)、[PostgreSQL 行锁](https://www.postgresql.org/docs/current/explicit-locking.html)、[OpenAI Chat Completions 接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 数据模型

业务表共 8 张。DDL 见 [schema.sql](schema.sql)。身份由已有的 Supabase `auth.users` 管理，首次登录事务内按 `user_id` 初始化钱包。

| 表 | 用途与约束 |
| --- | --- |
| `wallets` | 每用户一个 USD 钱包。账面余额和预占额分别维护，可用额为两者之差。 |
| `pricing_groups` | 分组代码、名称和启用状态。 |
| `models` | 对外模型代号、上游映射、上下文和输出上限。 |
| `model_rates` | 分组 × 模型的费率版本，记录三种 Token 单价和倍率。每对只保留一个当前版本。发布时在同一事务关闭旧版并新增。历史版本费率字段冻结。 |
| `api_keys` | 钱包归属、固定分组、密钥前缀、HMAC 摘要、状态、累计消费上限和 RPM 限制。切换分组时另建密钥。撤销保留历史引用。 |
| `usage_requests` | 每次已入场调用一条。记录归属、费率版本、上游请求 ID、Token、金额、耗时和状态。提供可选的密钥内幂等键。 |
| `redeem_codes` | 一次性码摘要、USD 面额、有效期、作废时间。实际核销关联由流水唯一约束保证。 |
| `wallet_entries` | 追加式流水，每个已结算请求最多一笔扣费，每个码最多一笔增额。复合外键校验请求和流水归属同一用户。 |

金额用整数微美元存储，`1 USD = 1,000,000 micros`。控制台 API 用十进制字符串传输这类金额。费率为每百万 Token 的微美元整数，倍率以万分比表示，`10000 = 1.0×`。时间戳用 UTC 保存，报表传 IANA 时区，以半开区间确定每天边界。应用更新可变行时同时更新 `updated_at`。

鉴权分两套。控制台从验证过的会话获取 `user_id`，所有用户读写显式按它限定，检查非本人的资源统一返回 404。网关从 Bearer 密钥摘要解析归属和分组，忽略请求体里的身份字段。密钥用高熵随机值与服务端 HMAC，显示明文仅限创建响应，响应禁缓存。独立凭据用于兑换码签发和迁移。私有 `gateway` schema 不暴露给浏览器或 Data API，运行库账号上线前只获得所需权限，流水只授予 SELECT/INSERT。禁止在应用日志记录密钥、原始请求和响应正文。

## API

共 14 个 HTTP 方法与路径组合。控制台写请求校验会话和同源，日期筛选设置范围上限。网关错误使用兼容错误体并返回本地请求 ID。所有上游请求发往固定的官方地址。

### S12 登录

| 方法与路径 | 调用者 | 输入 | 输出 |
| --- | --- | --- | --- |
| `POST /api/session/login` | 已受邀用户 | email、password | 建立会话并确保钱包存在。UI 只接受站内跳转 |
| `POST /api/session/logout` | 登录用户 | 无 | 清理会话，204 |

### F01 选型和接入

| 方法与路径 | 调用者 | 输入 | 输出 |
| --- | --- | --- | --- |
| `GET /api/catalog` | 登录用户 | 可选搜索词、分组 | 启用模型、分组、当前价和自有接入地址 |
| `GET /api/keys` | 登录用户 | 可选名称/前缀、cursor | 本人密钥摘要、状态、额度、RPM |
| `POST /api/keys` | 登录用户 | 名称、分组、额度、RPM | 201，ID 与一次性明文 |
| `PATCH /api/keys/:id` | 密钥所有者 | 名称、状态或限额 | 更新结果。已撤销的状态不可恢复 |
| `DELETE /api/keys/:id` | 密钥所有者 | ID | 幂等撤销，204 |
| `GET /v1/models` | 启用的 API 密钥 | Bearer | 分组可用的模型代号列表 |
| `POST /v1/chat/completions` | 启用的 API 密钥 | model、文本 messages、max_completion_tokens、可选 Idempotency-Key。支持非流式 | 成功时返回兼容 JSON 和 usage。余额或额度不足返回 402，超过 RPM 返回 429，不支持的参数返回 400 |

### F02 用量与费用

| 方法与路径 | 调用者 | 输入 | 输出 |
| --- | --- | --- | --- |
| `GET /api/dashboard` | 登录用户 | tz | 余额、预占额、启用密钥数、今日和累计汇总 |
| `GET /api/usage` | 登录用户 | from、to、key_id、cursor | 本人请求明细、状态、Token、标准费与实际扣费 |
| `GET /api/usage/summary` | 登录用户 | from、to、tz、key_id | 按日聚合、Top 模型以及筛选期汇总。账单只统计已结算金额 |

### F03 兑换

| 方法与路径 | 调用者 | 输入 | 输出 |
| --- | --- | --- | --- |
| `POST /api/redeem` | 登录用户 | 兑换码 | 增额流水 ID、面额和余额。同一用户重复提交返回原收据 |
| `GET /api/wallet/entries` | 登录用户 | kind、cursor | 本人扣费和兑换流水 |

F04 在首发不分配接口。首发无入站或出站 webhook，每 5 分钟扫描超时请求。未派发的过期预占可回收，已派发且缺少结算依据的请求进入待核对。对账命令每日比较钱包余额与流水净额、钱包及密钥预占额与未决请求总额，差异带请求 ID 报警。

## 调用、扣费与异常处理

1. **入场。** 校验请求体大小、模型、角色与输出上限。事务按钱包 → 密钥的顺序加锁，检查当前密钥状态、余额、密钥累计额度和前 60 秒已入场请求数。固定本次分组费率版本，按模型最大上下文及允许的输出上限保守估算并预占，缓存输入按较贵的输入费率估算。并发请求共享同一钱包。预占额可能高于实际费用，余额不足时页面提示补额。
2. **发出调用。** 预占回收和派发使用条件状态更新竞争 `reserved` 行。只有成功推进到 `dispatched` 的处理者才能发请求。提交事务后才做外部 HTTP，禁用 SDK 自动重试。收到有效用量后，将缓存 Token 从总输入拆出，按未缓存输入、缓存输入、输出三类加总。标准费是分组倍率前金额，实际费为分组倍率后金额。两者使用同一精确中间值，各自向上取整至微美元。
3. **结算。** 按钱包 → 密钥 → 用量行加锁，检查状态和快照。事务内写扣费流水、扣余额、释预占、更新密钥累计消费和调用状态。返回成功响应前确认事务提交。数据库约束兜底重复流水，跨表金额与状态一致性由服务事务保证。
4. **处理不确定结果。** 可证明未发出或未产生用量的请求释放预占。上游超时、回包缺用量、实际费用超过预占、或派发后进程中断时转待核对，保留预占并生成待办。只用可信上游凭据或经授权的运营决策关闭待办。无法取得依据时按运营阈值暂停该账户继续放量，避免悬挂金额累积。结算确认后若客户端断开，控制台仍可用请求 ID 查账。
5. **重复提交。** 可选幂等键按密钥区分，记录请求规范化摘要。相同键与同一请求只允许一次上游派发。重复提交返回 409 与原请求 ID/状态，完成时也不重放模型正文。相同键配不同输入返回冲突。未传幂等键的重复请求各自计费，需在接入文档披露。
6. **兑换。** 按钱包 → 兑换码行加锁。先查既有流水以支持同一用户重试，然后检查过期或作废状态，在一个事务里新增流水并增加余额。不同账号竞争同一码仅一笔可入账。对无效尝试做请求频率限制。

仪表盘口径需在验收前定死。请求数统计已入场请求，结算金额和计费用量只取已结算记录，按请求创建时间归档。用户可看待核对状态与预占。模型价格、分组倍率改动只影响新请求，历史账单用历史费率回算。

## 实现顺序

| 里程碑 | 页面及对应表 | 接口和验收 |
| --- | --- | --- |
| 1. 单模型跑通一次 | S12、S03、S04/S14、S01/S05 的最薄版本。钱包、分组、模型、费率、密钥、用量、流水 | 登录、模型目录、创建密钥、一次非流式调用、仪表盘/用量。用桩产生固定 Token 数和费用，核对一次调用只有一条匹配流水。 |
| 2. 接入官方上游并补齐约束 | S03、S04/S14、S01、S05。使用相同七张表 | 密钥列表/编辑/撤销、模型列表、用量筛选和曲线、超时恢复。用自有测试凭据验证非流式兼容。用并发用例验证余额和限额不会被重复占用，旧费率可复算。 |
| 3. 兑换并完成试点 | S08、S01。加入兑换码表 | 兑换、钱包流水和签发 CLI。用试点码验证到账和同码并发只入账一次，再用到账额度完成第二次调用。 |
| 4. 扩展 | 先补流式文本及相应结算验证，再评估多协议与外部购买。S02、S06、S07 等独立立项 | 若支持 SSE，需先将客户端取消、总结用量缺失和重连纳入对账验收。订单、支付与订阅模型在确认真实业务规则后单独设计。 |

三个主要风险是上游超时后的结算不确定性、跨版本费率和 Token 费用对账、不同请求并发抢占同一余额。下一阶段可用 `$replica-design` 展开 S01、S03–S05、S08、S12、S14 的首发交互，尤其是密钥一次性显示、余额预占和账单待核对状态。
