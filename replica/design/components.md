# ZeroCode MVP 首发交互设计

以 [MVP 架构](../architecture.md) 为实现范围，沿用 [调研报告](../recon.md) 的页面编号。采用原创的浅色控制台样式，靛紫用于操作，琥珀色用于待处理，青绿色用于已完成。工作区没有原站参考截图，色彩、字号和尺寸是本设计的选择。

## 首发页面和信息层级

| ID | 页面 | 从哪里进 | 首屏内容与主要操作 | 页面状态 |
| --- | --- | --- | --- | --- |
| S12 | 登录 | 未登录访问控制台 | 邮箱、密码、登录。登录后返回合法的站内目标页 | 待输入、提交中、账号或密码错误、请求失败、会话失效 |
| S01 | 概览 | 登录后的默认页 | 可用余额置顶，旁列账面余额和预占。其下是今日/累计请求、已结算费用、计费 Token 和启用密钥数。主要操作为查看用量、管理密钥、兑换额度 | 加载、首次使用、正常、存在预占、加载失败 |
| S03 | 模型与价格 | 侧栏、创建密钥前 | 搜索、分组筛选、当前输入/缓存读取/输出单价、分组倍率、适用接口。清楚标明每百万 Token 和 USD | 加载、单模型、多分组、无匹配、加载失败 |
| S04 | API 密钥 | 侧栏、S01 | 接入地址和复制按钮，密钥名、前缀、分组、状态、累计额度、RPM 和行菜单。主要操作为创建密钥 | 空列表、有记录、停用、撤销、无匹配、加载失败 |
| S14 | 创建与保存密钥 | S04 的创建按钮，弹窗 | 第一步填写名称、分组、累计额度和 RPM，第二步一次性显示完整密钥 | 编辑、提交、确定失败、结果未知、成功、复制成功或失败、离开确认 |
| S05 | 使用记录 | 侧栏、S01 查看用量 | 时间、密钥筛选，按日曲线、明细表和前后翻页。每条显示请求时间、模型、密钥前缀、状态和费用。展开行查看请求 ID、Token、预占和费用说明 | 加载、无记录、无匹配、按请求状态显示、刷新失败并保留旧值 |
| S08 | 兑换与余额流水 | 侧栏、S01 兑换额度 | 兑换输入、提交、成功收据、钱包流水。余额预占时继续显示可用额口径 | 待输入、提交中、不可用码、结果未知、成功、流水空态 |

登录页使用独立布局。登录区用同一顶部标题和侧边导航，导航依次为概览、模型与价格、API 密钥、使用记录、兑换与流水。桌面主内容最大 1184px，侧栏 224px，页头 64px，主要信息区留 24px 间距。低于 1024px 收起侧栏，使用顶部菜单。低于 640px 内容单列，账单行先展示时间、状态与费用，展开后可读完整字段。宽表仅在表格容器内横向滚动。

## 场景一：密钥只显示一次

| 触发 | 界面反馈和可执行动作 |
| --- | --- |
| 打开 S14 | 提前提示“完整密钥只在创建成功后显示一次”。分组选择旁提醒“创建后更换分组需要新建密钥”。为空的额度字段表示无密钥累计额度限制，仍受钱包余额约束。 |
| 提交创建 | 按钮显示“正在创建…”，屏蔽重复提交。服务器明确拒绝时保留表单并在对应字段反馈。请求超时或连接中断时显示“创建结果未确认”，提供“刷新密钥列表”。由用户核对新条目后再决定是否创建或撤销。 |
| 收到创建成功响应 | 切换到“保存 API 密钥”，显示名称、分组、只读明文和“复制密钥”。从弹窗标题开始读屏，密钥字段可手动选择。用户确认“我已保存”后可点“完成”。复制成功仅提示“已复制”，弹窗保持打开。 |
| 剪贴板失败 | 保留明文和焦点，提示“复制失败，请选中密钥后手动复制”。用户仍可手动备份和完成。 |
| 用户尝试提前关闭 | Esc 或关闭按钮进入弹窗内的确认状态。焦点落在“继续保存”，另有“关闭并隐藏密钥”。点击遮罩保持当前步骤。确认继续保存时回到展示步骤。刷新或离开页面时，明文随展示生命周期结束。 |
| 完成、确认关闭或会话失效 | 清除组件状态和字段内容，回到 S04。列表仅显示名称、前缀和状态。如遗失明文，用户可创建替代密钥、更新自己的工具，再撤销旧密钥。 |

实现边界：明文仅来自 `POST /api/keys` 的一次性响应。前端只在当前弹窗内存保留，关闭、卸载或退出时清除。响应使用 `Cache-Control: no-store`，密钥字段排除在分析、录屏和错误日志之外。浏览器返回缓存恢复页面时清除展示。用户主动复制后由用户管理剪贴板。创建、复制和成功关闭的提示可读屏，提示文本不含密钥。

## 场景二：余额预占

S01 把“当前可用于新请求的额度”放在第一层。三项金额从同一次钱包快照渲染，避免刷新时数字短暂不一致。收据和明细统一保留微美元精度，最少两位小数，最多六位。小额不会因显示舍入变成零。

| 状态 | 账面余额 | 预占金额 | 可用余额 | 文案及动作 |
| --- | ---: | ---: | ---: | --- |
| 调用前 | USD 10.00 | USD 0.00 | USD 10.00 | 正常展示 |
| 已为本次请求预占 USD 2.00 | USD 10.00 | USD 2.00 | USD 8.00 | “这笔额度暂留给处理中或待核对的请求。”可转到使用记录 |
| 确认实际扣费 USD 0.75 | USD 9.25 | USD 0.00 | USD 9.25 | 已结算费用增加 USD 0.75，未用的 USD 1.25 随预占释放 |
| 确认请求无需扣费并释放 | USD 10.00 | USD 0.00 | USD 10.00 | 与上一行是互斥结果。记录显示“已释放”，流水无扣费 |

余额低于下一次调用所需预占时，网关返回 402，接入说明解释“可用余额不足以预留本次费用”。账户余额不足引导到 S08。密钥累计额度不足则引导到 S04 检查该密钥限额。控制台刷新失败时保留上次快照和更新时间，显示“余额暂未更新”，初次加载失败显示占位与重试。已结算费用和待处理请求分开呈现。

## 场景三：账单待核对

| 数据状态 | 标签 | 费用列 | 展开后的动作和信息 |
| --- | --- | --- | --- |
| `reserved` / `dispatched` | 处理中 | 结算中，附预占额 | 展示请求 ID、发起时间和刷新入口 |
| `review` | 待核对 | 待确认，附预占额 | “这次请求的费用仍在核对，预留额度会在核对完成后更新。”显示请求 ID、发起时间、最近更新时间、复制请求编号、刷新 |
| `settled` | 已结算 | 显示实际已扣费，可为 USD 0.00 | 展开可比较标准费和实际费，说明分组倍率。如有付款流水，可在 S08 查阅 |
| `released` | 已释放 | 无扣费 | 曾预占的金额已解除，详情中呈现对应说明 |

待核对行保留原请求时间和分页位置，保留相同请求 ID。费用未确认时沿用原有预占，费用汇总仅计入已结算记录。页面不显示预计完成时间。刷新沿用同一条记录更新状态与金额。待核对详情不提供“重新调用”或“取消扣费”操作，用户可拿请求编号联系已有支持渠道。按同一请求幂等键重试时，客户端可能得到 409 和原请求 ID，按原记录查询。使用新请求产生的新费用另算。

两个发布前的接口约定需要补进实现任务。第一，控制台应能区分 402 的钱包余额不足与密钥额度不足，建议稳定错误码 `insufficient_balance` 和 `key_budget_exceeded`。第二，S05 从 S01 打开时先进入现有用量页。若要直接定位一个请求或筛选待核对，建议为现有 `GET /api/usage` 增加可选 `request_id` 和 `status`，首发可按实际接口进度决定是否展示这两个控件。用量响应需要包含请求 ID、状态、预占额、最近更新时间与可空金额，以实现上述基本状态。

## 组件规格

| 组件 | 规格与通用状态 | 键盘、读屏与使用位置 |
| --- | --- | --- |
| 导航栏与移动菜单 | 当前项高亮、悬停、可见焦点。移动面板用原生导航与按钮 | 当前项用 `aria-current="page"`，关闭菜单后焦点回到触发按钮。S01、S03–S05、S08 |
| 按钮 | 主、次、文字、危险四种。高 32/40/48px，触屏常用操作取 44px 以上。默认、悬停、按下、焦点、禁用、提交中 | 使用原生按钮，加载保留动作名并用简短文字表达进度。所有页面 |
| 输入框与选择框 | 文本、密码、金额、日期、分组、搜索。默认、焦点、无效、只读、禁用 | 显式 label，错误和帮助用 `aria-describedby`，失败聚焦错误字段。S12、S03–S05、S08、S14 |
| 弹窗与确认步骤 | 创建、展示、提前关闭、撤销不可逆确认。40px 操作按钮，内容最多 480px | 焦点留在弹窗，Esc 触发对应关闭流程，离开后恢复焦点。S04、S14。参照 [WAI 弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |
| 一次性密钥与复制 | 明文仅在展示步骤，单行可横向查看，支持选择。复制中、成功、失败 | 密钥值不进入实时播报。复制反馈用 `role="status"`。S14。S04 的接入地址复制可复用同一反馈 |
| 余额摘要与统计卡 | 可用、账面、预占口径，数字等宽对齐。加载、零额度、预占、旧值、错误 | 金额和币种同读，单次更新聚合播报。S01、S08 |
| 状态标签与消息 | 中性处理中、警示待核对、成功已结算、中性已释放。图标可选，文字常驻 | 状态依靠文字表达，异步反馈只播报有意义的变化。S01、S04、S05、S08 |
| 筛选栏、数据表和分页 | 筛选改变即重置游标，已选条件可清空。表格列头、展开详情、加载、空态和错误 | 列头与单元格关联，详情按钮有行上下文及 `aria-expanded`，分页可键盘操作。S03–S05、S08 |
| 用量曲线 | 展示日粒度 Token 或已结算费用，提供同口径数据表 | 不用颜色独自区分系列，数据表可读可导航。S05 |
| 首次使用、无匹配和请求失败 | 首次使用给下一步，无匹配可清空条件，失败区可重试，刷新失败保留旧数据 | 使用描述性标题和错误状态，避免用空态代替故障。S01、S03–S05、S08 |

## 设计令牌与验收

[tokens.json](tokens.json) 保留技能的角色结构。[tokens.css](tokens.css) 提供 CSS 变量。[tailwind-theme.css](tailwind-theme.css) 把颜色、排版、尺寸和阴影映射到 Tailwind CSS v4。所有交互使用可见焦点，普通正文至少 4.5:1，控件边界和焦点至少 3:1。遵循减少动态效果偏好。使用系统中文字体栈和系统等宽字体。

[交互预览](preview.html) 用示例数据演示密钥展示、钱包预占和请求核对。可直接在浏览器打开，也可查看[预览截图](preview.png)。

1. 创建成功后无论是否复制，关闭、返回和刷新都不能再次看到原密钥明文。复制失败时可键盘选择并手动复制。提交结果未知时不自动重复创建。
2. 预占、结算、释放三种变化均满足“可用余额 = 账面余额 − 预占金额”，三项来自同一快照。待核对金额不进入已结算费用汇总。
3. 待核对行的请求 ID 在刷新后保持不变，金额显示“待确认”，可明确区分零费用、释放和仍未结算三种结果。
4. 键盘可到达所有主要操作。弹窗内外焦点、移动窄屏、剪贴板失败和读屏播报在正式接线后验证。
