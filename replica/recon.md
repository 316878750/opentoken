范围：登录后面向普通用户的模型选型、API 接入、用量核对和充值兑换，以及同一侧栏可见的辅助功能。面向后续评估同类功能的开发者。调研日期为 2026-11-19。

## 核心循环

查看模型和分组价格 → 选择分组并配置 API 密钥 → 通过外部 AI 工具发起调用 → 回到仪表盘和使用记录核对用量 → 需要时购买并兑换补充额度。外部调用和实际扣费属于待实测环节。

## 核心流程

| ID | 用户目标 | 页面路径 | 已观察与待验证 |
| --- | --- | --- | --- |
| F01 | 选型和 API 接入 | S01 → S03 比较费率 → S04 → S14 配置密钥 → 外部 AI 工具 | 已验证页面和打开弹窗。创建成功、凭证显示方式、外部调用及请求入账未执行。从 S04 到 S14 为 1 次点击。全程点击数待实测 |
| F02 | 核对用量和费用 | S01 查看汇总 → S05 按密钥和时间筛选 → 查看曲线和记录 | 筛选和分页入口、含数据页面已见。单次筛选结果、实际/标准费用的计算关系和空结果待验证。从 S01 到 S05 为 1 次导航点击 |
| F03 | 补充余额 | S01 → S02 → 卡网购买 → S02 或 S08 输入兑换码 → S01 查看余额 | 站内操作入口和购买顺序可见。付款、兑换和余额变动未执行。完整点击数、无效、重复、过期码反馈待实测 |
| F04 | 查看订阅和订单 | S01 → S06 或 S07 | 两个目标页都是 1 次侧栏导航。验证了当前账号的空状态。有数据的状态待核查 |

待验证边界包括未选择分组、密钥失效、达到额度或速率限制、筛选无数据、重复或无效兑换。它们是验收候选场景，未观察到页面响应。

## 推测的数据模型

此处描述可见的产品对象，不代表 ZeroCode 的实际数据库结构。

| 逻辑对象 | 可见字段或观察依据 | 置信度 |
| --- | --- | --- |
| Account | 余额、用户名、邮箱、头像及账户安全设置。S01、S11 | 高 |
| ApiKey | 名称、分组、启用状态、IP/额度/速率限制、有效期。S04、S14 | 高 |
| ModelPrice | 模型、计费方式、输入/输出/缓存读取单价。S03 | 高 |
| PricingGroup | 分组、平台、倍率。S03、S04、S14 | 高 |
| UsageRecord | 可按密钥和日期筛选，页面展示 Token 和费用指标。S01、S05 | 中。逐条记录字段及结算匹配关系待查 |
| Redemption | 兑换码、兑换动作和最近活动区。S02、S08 | 中。码的种类、面值和状态规则待查 |
| Subscription / Order | 存在独立页面。S06、S07 | 低。缺少记录样本，生命周期与字段未确认 |
| Channel / AgentApplication | 渠道时间窗与代理申请的联系方式、说明。S09、S10 | 中。状态、审核和权限字段待查 |

推测关系：账号可以有多把密钥，密钥可以选择分组，使用记录可按密钥归集。一次调用如何映射到分组和费率版本、兑换如何关联订单或订阅，界面证据不足。

## 功能矩阵与范围

见 [features.csv](features.csv)。`original=yes` 代表已看到相应页面、控件或明确引导，`notes` 记录验证深度。建议优先级供后续复刻评估，`clone` 初始均为 `no`。未观察到的结算规则、错误响应和后台管理能力留在报告里的待验证项。

范围外包括原站品牌素材、私有实现、真实密钥和用户数据、卡网或上游供应合作关系、管理员侧配置和结算操作。未验证移动端、表单错误态和权限差异。

## 规模初判

共记录 11 个已打开的站内主页面、1 个登录跳转页、1 个外部教程入口和 1 个密钥弹窗，梳理了 4 条用户流程。若只做面向普通用户的核心流程，暂估 M。若加入真实多协议网关、用量账本和交易对账，需要另行估算。

实现难点集中在三处：密钥与限额的执行、Token/缓存及分组倍率的账本对账、兑换与余额流水的一致性。在转入 `$replica-architect` 前，建议优先用测试账号补齐一次接入、一次费用核对和一次可控的兑换状态验证。
