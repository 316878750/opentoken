# OpenToken 第 7 阶段实施计划

> 实现按小段验收，已验证的工作备份到 GitHub，正式试点继续使用 main。

**目标**是把试点后的接入和运营能力扩展到流式调用、更多模型与分组、用量趋势、在线支付与订阅。

## 7.1 流式输出

- [x] 在 `tests/loop.test.mjs` 验证 SSE 分块、一次预占与一次流水、取消连接后的结算。使用隔离数据库与模拟上游。
- [x] 在 `lib/http.ts` 接受 `stream: true` 与可选的 `stream_options.include_usage`。在 `lib/gateway.ts` 让 JSON 和 SSE 共用派发及账务事务。先让 `mock-text` 用分块输出验证协议和结算。
- [ ] 接入支持最终 usage 帧的上游。官方 OpenAI Chat Completions 请求上游发送 `include_usage: true`。上游成功结束且用量有效时结算，结果不明时保留预占并进入待核对。客户端断开后，网关在自身时限内继续读取上游。真实调用单独确认模型与凭据。
- [ ] 验收普通 JSON 路径兼容、并发限额、重复幂等键、断流、缺失或超预算用量，以及 SSE 正常结束。

开发分支已通过构建与 32 项回归。模拟流结算与非流式路径使用相同账务事务，测试覆盖完整读取和客户端主动断开。

## 7.2 更多模型与分组

- [ ] 沿用现有模型、分组、费率版本和密钥归属。把目录、报价与上游选择从单一运行配置扩展为各模型明示的别名、上游、限额与能力。
- [ ] 运营入口只允许发布已配置的模型和费率版本。API 密钥只能访问自己分组的启用模型。验收历史费用不受新费率影响。
- [ ] 选择真实模型时确认供应商、模型 ID、输入与输出上限、缓存计价及可用协议。使用测试上游验证跨分组隔离，再按确认的范围实测。

## 7.3 用量趋势

- [ ] 从当前账号的用量记录按本地自然日汇总请求数、已结算 Token 与扣费，补齐没有用量的日期。
- [ ] 仪表盘显示最近 7 天与 30 天。验收跨时区日期边界、空状态，以及趋势总额和账本口径一致。

## 7.4 在线支付与订阅

- [ ] 在沙盒中验证托管结账、订单与支付回调。以验签后的服务端事件确认支付，按支付对象唯一键幂等入账，处理失败与重发。
- [ ] 用订阅账期和事件管理权益。用户确定支付商、可用地区、币种、套餐与退款口径后，再确定正式接入配置和上线验收。真实扣款单独授权。
