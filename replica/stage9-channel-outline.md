首发范围已确认。创建渠道草稿，测试上游，手工绑定模型与分组，显式启用，再验证调用、停用和回退。

## Enkinfo 调研

- 渠道列表可按供应商类型切换，并按渠道、模型关键字、分组和状态筛选。列表展示状态、响应时间、已用和剩余额度、优先级、权重。行内有测试、启停和编辑入口。
- 已查看「添加渠道」空白表单，默认类型为 OpenAI。界面标为必填的是类型、名称、密钥和模型。组织可选。官方渠道可以使用内置地址，第三方可填自定义 API 地址。模型支持选择、手工填入和获取模型列表。分组预填 `default`，可设置模型重定向、默认测试模型和自动禁用。
- 高级设置包括上游模型变化检测与自动同步、参数和请求头覆盖、状态码映射、标签和备注、优先级和权重，以及代理、提示词和字段透传控制。此次查看到表单与提交入口，保存、实际调用、自动禁用和路由规则均未经实测。[Enkinfo 渠道管理](https://agent.enkinfo.com/console/channel)

## OpenToken 首发表单

| 信息 | 拟定规则 |
| --- | --- |
| 渠道名称、类型 | 必填。首发支持官方 OpenAI、第三方 OpenAI 兼容文本。官方使用固定地址。 |
| API Base URL | 兼容渠道必填，由服务端核验批准的 HTTPS 目标；页面显示规范化后的地址和实际请求路径。保留供应商所需的 `/v1` 等前缀，避免重复拼接接口路径。 |
| 供应商密钥 | 选择服务端已登记的密钥引用。首发沿用受控部署配置保存密钥，后台只展示配置或验证状态。密钥轮换走单独的测试和发布步骤。 |
| 上游模型与测试模型 | 允许手工填写上游模型 ID。测试时显式选择一个模型。配置生效前核对流式能力和输出限制。 |
| 对外模型与分组 | 渠道可关联多个上游模型。发布时选择 OpenToken 对外模型、对应上游模型 ID 和可用分组。一个对外模型与分组组合只有一条生效路由。 |
| 备注 | 可选，仅有管理权限的人员可见。 |

首发实行单路由发布。分流、自动切换和自动上线的策略在 9.3 一并纳入渠道版本配置。价格由模型管理维护，沿用输入、缓存读取和输出的版本化费率。渠道草稿可先单独测试，公开调用前才要求完整的模型、分组和费率绑定。[现有上游配置](../lib/upstream-config.mjs) · [第 9 阶段规划](stage9.md)

## 管理流程与权限

1. **建草稿。** 系统管理员填写基本信息。草稿在渠道列表可见，用户目录和网关均无法使用该渠道。
2. **测试指定版本。** 用当前草稿及密钥引用验证指定上游模型，记录操作编号、成功或失败、耗时和脱敏错误。区分认证失败、模型不可用、超时和结果不确定。真实模型探针可能产生上游费用，隔离验收先使用模拟上游。探针不写用户钱包流水。
3. **预览并启用。** 展示受影响的模型与分组。发布要求当前版本测试通过，并验证模型映射、分组和有效费率。修改地址、密钥或模型映射后，候选版本需重新验证。
4. **编辑、轮换或停用。** 编辑先保存为草稿版本，发布后才接新请求。轮换先测试新密钥再切换，记录操作者、原因和版本。停用立即阻止后续派发，已派发请求按原路由和费率完成结算。回退时重新检查密钥可用性和当前停用状态。

系统管理员可以新增、编辑、测试、启停和轮换。运营人员只看脱敏状态、绑定概览和测试结果，审计员通过操作日志追溯。普通用户和网关 API 密钥无法访问渠道管理接口。每次管理操作都由服务端检查角色，敏感变更复用第 9 阶段的近期身份验证与原因记录规则。[权限矩阵](stage9.md#权限矩阵)

## 开发顺序

| 顺序 | 交付 | 隔离验收 |
| --- | --- | --- |
| 1. 数据与页面 | 渠道清单、草稿和版本、密钥引用，提供列表、筛选、新增和详情。 | 新建草稿可查，普通用户及运营写请求被拒。浏览器响应、操作日志和错误信息均无密钥明文。 |
| 2. 探针与审计 | 使用现有上游适配器做定向测试，记录结果和审计。探针与正常请求共用受控的出站规则和超时。 | 成功、无效凭据、模型不可用和超时可区分。测试结果对应确切配置版本，用户钱包与账本无变动。 |
| 3. 模型映射与派发 | 接入模型和分组绑定，使用生效版本生成目录。每笔请求保存渠道、映射和费率版本。 | 用户目录、`/v1/models` 和实际路由一致。流式及非流式调用的预占、实扣、释放和钱包账本相符。 |
| 4. 迁移与回退 | 比对现有环境配置和待发布配置，导入现有试点路径，演练启停、轮换和回退。 | 迁移前后的模型别名、分组、费率和可用性对得上。停用后新请求无法派发，已派发请求正常结算。回退保留历史账单，已撤销密钥不会恢复。 |

## 策略配置与启用条件

| 策略 | 9.3 可配置项 | 规划的运行规则与验收 |
| --- | --- | --- |
| 权重分流 | 每个渠道版本保存优先级和 1–100 的权重。默认优先级 0、权重 100。 | 仅纳入同一模型与分组中已发布、兼容且通过测试的渠道。在最高可用优先级内按权重选择一个渠道，请求受理后固定选择和费率。启用前用模拟流量核验比例、渠道排除和历史账本一致性。 |
| 自动切换 | 开关、候选渠道、连续失败阈值和冷却时间。未设置时按连续 3 次、冷却 60 秒规划。候选必须覆盖相同模型、分组与流式能力。 | 切换针对后续请求。已派发或可能计费的请求继续按原路由结算，结果不明时进入核对。启用前演练并发切换、冷却和失效候选。 |
| 模型自动上线 | 精确上游 ID 清单、指定分组与目录检查间隔。未设置时按 60 分钟规划。清单仅接受该分组中已手工绑定且有明确费率的模型。 | 上游目录发现需通过接口及用量验证，再按已批准的分组、费率及映射发布。启用前演练目录重复数据、变更、缺价、下架与回退。 |

这些配置随渠道版本保存。首发运行模式为 `single_route`，只使用管理员显式发布的绑定，策略设置可在隔离环境配置并读回。策略执行需经过上表各项专项验收及启用确认。
