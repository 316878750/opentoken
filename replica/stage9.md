# OpenToken 第 9 阶段 · 系统管理员后台

目标是让管理员在浏览器完成日常运营，让配置、额度和权限变更可追溯。首发范围包括渠道管理、模型管理、兑换码管理、用户管理、登录日志、操作日志和系统设置。第 9 阶段可在隔离环境独立推进，8.3 小范围付费试点继续暂停。[项目进度表](progress.md)

## 参考后台与项目现状

2026 年 11 月 21 日，使用已登录的管理员会话查看了 Enkinfo 渠道页。页面提供按供应商类型浏览、按渠道或模型及分组筛选，并展示渠道状态、响应时间、优先级和权重。行内有测试、启停和编辑入口。侧栏可见模型管理、用户管理、登录日志、操作日志和系统设置。电脑操作工具在页面切换时无法确认浏览器地址，其余模块只确认入口，内部表单、后端架构和权限实现未验证。本次参考的是功能划分和交互入口，OpenToken 的兑换码管理来自现有业务流程。[Enkinfo 渠道管理](https://agent.enkinfo.com/console/channel)

OpenToken 已有 Supabase Auth、PostgreSQL、受限应用数据库角色、模型目录、分组费率版本和账本。渠道与模型发布依赖环境配置和 `db:seed`，用户邀请、签发兑换码和人工账务处理有运营命令。第 9 阶段拟在现有 Next.js 应用内增加 `/admin` 页面及专用服务端接口，复用上述身份、计费和入账逻辑。独立管理应用可提供独立部署边界，但会增加身份、发布和数据一致性成本，当前试点规模下先采用同应用的独立权限边界。[MVP 架构](architecture.md) · [现有模型发布](stage7.md#72-更多模型与分组) · [试点邀请](deploy.md)

## 权限矩阵

以下是首发拟定角色。管理员身份绑定已验证的 Supabase 用户 ID，角色只由授权的服务端流程管理。普通账号及 API 密钥均无后台权限。

| 模块 | 系统管理员 | 运营人员 | 审计员 |
| --- | --- | --- | --- |
| 渠道管理 | 新建、编辑、测试、启停、轮换密钥引用 | 查看脱敏状态和测试结果 | 通过操作日志查询变更 |
| 模型管理 | 新建、映射、上下架、发布分组与费率 | 查看模型、分组和已发布费率 | 通过操作日志查询变更 |
| 兑换码管理 | 签发、作废未使用码、查询发放与兑换结果 | 在系统额度限制内签发和作废自己发放的未使用码，查询本人发放结果 | 查看脱敏发放和兑换摘要 |
| 用户管理 | 查询、邀请、停用与恢复、分配后台角色 | 查询脱敏用户资料、邀请普通用户 | 无用户管理权限 |
| 登录日志 | 查询 | 无 | 查询脱敏日志 |
| 操作日志 | 查询 | 查询本人操作的脱敏记录 | 查询脱敏日志 |
| 系统设置 | 编辑允许在线修改的设置，查看版本 | 查看当前可公开给运营的设置 | 通过操作日志查询变更 |

- 每次后台读写均在服务端验证会话、重新检查账号状态与所需权限。后台 API 未登录返回 `401`，越权返回 `403`。后台页面引导访客登录，对已登录的无角色账号返回 `404`。后续后台写操作校验同源。通过后台变更角色、轮换渠道密钥和发布价格时，需同一账号在 10 分钟内重新验证身份并记录原因。系统拦截自行提权，以及通过停用或撤权移除最后一位有效系统管理员。
- 管理员首开由受控运维流程绑定已确认账号。撤销角色后，既有会话的下一次后台请求立即失去权限。API 密钥继续只用于网关，权限判断使用当前账号状态。
- 审计日志由应用追加，后台角色只能查询授权范围。对数据库内写入及其审计记录使用同一事务。邀请、渠道测试等外部操作先落操作编号，再记录结果。结果未知时先核对外部状态，再决定是否重试。

## 七项功能与验收标准

| 模块 | 首发功能与数据约束 | 可验证的验收标准 |
| --- | --- | --- |
| 渠道管理 | 按供应商、状态、模型关联筛选，维护名称、供应商类型、允许的 HTTPS 地址、密钥引用和启停状态。普通后台查询只返回密钥配置状态。测试有明确目标及超时，结果记录测试时间、耗时和脱敏错误。 | 建立隔离渠道，验证成功、鉴权失败和超时三种结果。测试和轮换不产生用户扣费，后台响应及日志不含明文密钥。停用后新请求不再选中该渠道，已派发请求仍可完成结算。 |
| 模型管理 | 管理对外模型代号、渠道模型 ID、流式能力、分组、上下架和每百万 Token 的输入、缓存读取及输出费率。每个模型与分组组合首发使用一条已发布渠道映射。沿用微美元整数和版本化费率。 | 发布一个隔离模型后，授权分组的目录、`/v1/models` 和实际调用一致。调价只影响新请求，历史与已入场请求仍按原费率核对。下架或渠道停用后不能发起新调用，历史账单仍可查。 |
| 兑换码管理 | 单次签发、面额和有效期、状态筛选、未使用码作废、发放与核销追溯。签发的首次成功响应显示明文，数据库存储摘要并复用现有赠送额度入账路径。 | 运营超限或尝试作废他人发放的码被拒绝。过期和作废码无法兑换。两名用户并发兑换只有一笔赠送额度入账，同一用户重试读回原收据。模拟签发响应丢失后重试，只有同一码的状态和编号可查。核对钱包余额、流水和审计记录。 |
| 用户管理 | 分页查账号、邮箱确认状态、账号状态和钱包摘要，支持邀请、停用、恢复及分配后台角色。补额走兑换码和账本。 | 邀请能用现有流程完成登录。停用对 OpenToken 新登录、既有控制台会话和已有 API 密钥的新请求均生效，并保留历史账本和已派发请求的结算。恢复后可重新登录。越权角色变更被拒绝。 |
| 登录日志 | 记录经 OpenToken 登录入口的成功、失败和限流，含时间、可识别的用户 ID 或脱敏标识、结果、原因类别、请求 ID。按时间、结果、用户标识筛选。 | 模拟成功、错误凭据及限流，各有可筛选的对应事件。日志和响应中无密码、会话令牌或原始请求内容，普通用户无法查询。 |
| 操作日志 | 按时间、操作者、动作、对象、结果筛选。记录服务端认证的操作者、目标、请求 ID、原因及脱敏前后值。记录高风险拒绝及外部动作的已完成、失败或待核对结果。 | 改价、签发与作废兑换码、停用用户、角色变更、渠道测试、系统设置变更均可追溯。模拟审计写入失败时，同一事务内的管理变更一并回滚。后台无编辑和删除日志入口。 |
| 系统设置 | 首发支持站点公告、支持链接、默认展示时区和运营签发额度上限。设置使用具名字段、类型校验和版本，回退以新增版本执行。供应商与基础设施密钥继续通过受控配置管理，Stripe 正式收款开关留在 8.3。 | 授权变更在下一次有效读取后可见。非法值、未开放的配置字段、同时覆盖旧版本及越权写入被拒绝。回退后恢复原有效值，并可核对两次审计记录。 |

## 数据和接口边界

- 新增管理员角色绑定、用户运行状态、渠道与密钥引用、模型渠道映射、登录事件、操作审计和设置版本等数据。沿用既有 `models`、`pricing_groups`、`model_rates`、`redeem_codes`、`wallets`、`wallet_entries`。请求入场固定已发布的渠道映射和费率版本，避免配置改动重算在途或历史请求。
- 管理接口按七个模块分组。读取分页并返回脱敏字段，写操作显式区分测试、发布、启停、签发、作废、邀请和角色变更。涉及重试的写操作用幂等操作编号，版本变更校验预期版本。后台入口和接口分别验权，浏览器不会获得数据库或上游服务凭据。
- 渠道地址按服务端批准的供应商目的地校验，探针与正常调用共用出站约束和超时。首发使用现有 OpenAI 兼容文本适配器，每个模型和分组确定一个可用渠道。密钥轮换经测试后切换，新派发使用新引用，已派发请求沿用原引用直到完成或超时。已撤销的旧引用不得随配置回退恢复。9.3 预先规划、保存和校验权重分流、自动切换和模型自动上线的策略，首发按单路由运行。[渠道管理与策略](stage9-channel-outline.md)
- 迁移先做现有配置与待发布配置比对，列出模型、分组、渠道和价格差异。隔离验证后由数据库已发布版本作为唯一配置来源，旧 `db:seed` 对渠道和模型仅保留比对用途。回退通过重新发布数据库内上一有效版本完成，重新校验当前渠道启停和密钥状态，保留账本及审计记录。
- 首发拟按每位运营人员设单码面额和 UTC 自然日累计签发上限，签发与额度占用原子完成。作废不返还当日限额。若首次响应丢失，以原操作编号查询签发结果，通过作废未使用码再重新签发处理。

## 9.1 运行与验收

`/admin` 和 `GET /api/admin/session` 从现有 Supabase 会话取得用户 ID，每次从 PostgreSQL 读取有效角色。9.1 的三种角色均可进入同一个后台入口，具体模块权限随各子阶段交付。角色绑定要求已确认邮箱且账号未封禁或软删除。撤权只影响后台访问，正常控制台会话仍可用。[Supabase Auth 用户模型](https://github.com/supabase/auth/blob/master/internal/models/user.go)

本地或隔离环境先应用迁移 008，再使用同一环境的 `MIGRATION_DATABASE_URL` 执行授权。账号 UUID 来自该环境已确认的 Supabase 用户。删除有角色的账号前先撤销其角色。

```powershell
pnpm db:migrate
pnpm db:check
pnpm db:admin grant USER_UUID system_admin initial_setup
pnpm db:admin grant STAFF_UUID auditor staff_change
pnpm db:admin revoke STAFF_UUID role_review
```

变更原因使用 `initial_setup`、`staff_change`、`role_review` 或 `incident_response`。成功变更与审计同事务写入。被业务规则拒绝的角色变更也落审计，命令输出可关联的审计编号。审计记录数据库连接角色，网页访问记录经过验证的账号。应用数据库角色只能通过授权函数追加后台访问审计，登录事件也只允许追加。普通用户会话越权有审计事件，访客或仅持 API 密钥的请求在会话校验时拒绝。登录审计覆盖应用登录入口的已解析请求，使用带密钥的邮箱摘要，并记录登录结果，不保存密码或会话令牌。

2026 年 11 月 21 日，在本地 Next.js、PGlite 的 PostgreSQL 协议端点和模拟 Supabase Auth 上完成验收。`pnpm build` 通过，`pnpm test` 56 项通过。

| 场景 | 实际结果 |
| --- | --- |
| 普通账号打开后台 | 控制台隐藏入口。直开 `/admin` 返回 `404`，请求会话 API 返回 `403` 并记录拒绝事件。用户元数据中的角色字段也无法获得权限。 |
| 仅持有效 API 密钥打开后台 | 普通账号和管理员持有的密钥均可请求 `/v1/models`。仅携带密钥访问后台 API 返回 `401`，浏览器打开后台引导至登录。 |
| 授权和撤权 | 同一会话在授权后进入后台，撤权后下一次后台页面和 API 请求立即失去权限。普通控制台请求仍成功。 |
| 账号状态与审计 | 封禁和软删除的账号无法继续进入后台，也不计入可用管理员。撤销最后一名有效管理员被拒并留痕。核对角色变更前后值、登录成功、失败及限流的审计记录。 |

正式发布前确认首批管理员账号，后续实现分别确认运营签发额度和日志留存周期。

## 9.2 兑换码管理

在隔离环境先运行 `pnpm db:migrate` 至 009，登录后从 `/admin` 打开兑换码管理。系统管理员可签发、查询和作废后台发放的码。运营只能查询和作废本人签发的未使用码。审计员可查看脱敏列表，签发和作废权限由服务端拒绝。已有命令行发放的试点码和历史兑换结果继续沿用原流程。

运营签发由 `OPERATOR_REDEEM_SINGLE_USD` 和 `OPERATOR_REDEEM_DAILY_USD` 分别限制单码面额及每位运营人员 UTC 自然日的累计面额。两个值均须为正数，空值或无效值关闭运营签发。额度与签发在同一事务检查，作废仍占用当日额度。系统管理员签发不使用运营限额。隔离测试使用单码 USD 2、每日 USD 3，正式值待确认。

签发使用申请编号去重。首次成功响应返回明文，列表与重试响应只返回记录信息。同一浏览器标签页刷新时保留未确认申请的编号、面额和有效期，用于核对原申请。明文不会写入浏览器存储、数据库或审计，关闭展示时清除。找回的记录没有明文时，可作废未使用码后重新签发。

签发和作废通过响应的 `X-Request-Id` 关联管理审计。核销审计按兑换码记录编号和钱包收据关联。签发、作废及首次到账的审计均随对应业务事务提交，重试沿用已保存的结果。后台码到账调用现有钱包函数，继续使用原有的防并发与同账号重试规则。

2026 年 11 月 21 日完成隔离验收。`pnpm build` 通过，`pnpm test` 57 项通过。兑换码专项另在只监听本机的 PostgreSQL 17.12 实例通过，身份服务使用合成账户。

| 场景 | 实际结果 |
| --- | --- |
| 签发与明文 | 同一申请并行提交返回一次 `201` 和一次 `200`，只有 `201` 含明文。重试、查询和审计均无明文。 |
| 角色与额度 | 普通用户被拒，审计员只读脱敏数据。运营无法作废其他账号所发的码。USD 2.01 超单码上限，累计已发 USD 2 后并发签发两份 USD 0.75 只有一份成功。作废后仍占用额度。 |
| 并发核销与对账 | 两个用户并发兑换同一个 USD 2 兑换码，只有一个钱包到账，另一个余额为零。重试返回原收据。兑换记录、钱包流水和核销审计的编号与金额一致。 |
| 作废与事务回滚 | 作废码无法兑换，重复作废只记一笔成功审计，已核销码无法作废。模拟核销审计写入失败时，钱包余额和流水均回滚，兑换码可再次尝试。 |

## 9.3 渠道管理与模型绑定

隔离环境先迁移至 010。部署配置 `CHANNEL_CREDENTIALS_JSON` 登记引用名称、适配器、经批准的基础地址和专用环境变量名。密钥明文由该环境变量提供，渠道版本只保存引用和校验指纹。同一密钥变量只绑定一个目的地。轮换时登记新的独立引用，测试并发布新版本。撤销旧引用或改变它的密钥、地址后，旧版本不可回退。官方适配器固定使用官方地址。[登记格式](../.env.example)

管理员从 `/admin/channels` 新增渠道，选择已有的定价模型与分组，并填写供应商模型 ID。探针按绑定的真实费率规则核验用量。支持流式的绑定同时验证非流式与流式响应。启用和回退要求近期登录、变更原因、有效密钥和适用于当前费率版本的成功测试。停用与发布使用同一数据库路由锁，账务受理时保存实际渠道版本及费率版本。探针和正式派发遵循现有真实上游及流式开关，Stripe 沙盒不执行真实探针。

管理页提供环境配置比对。迁移期间，尚未接管的模型与分组仍使用现有环境配置。发布后，以数据库绑定为准，停用或撤出绑定时也不会退回旧环境路由。`db:seed` 对已接管的模型与分组不覆盖费率。全部迁移后，可用 `UPSTREAM_MODE=managed` 关闭旧路由来源，管理渠道仍受 `ENABLE_OPENAI` 与 `ENABLE_UPSTREAM_STREAMING` 控制。

优先级、权重、自动切换候选和阈值、自动上线清单与分组都可在草稿中配置、校验和读回。配置随版本一起发布和回退。运行模式 `single_route` 只接受每个模型与分组的一条已发布路由，自动策略的执行条件与验收已在本阶段定义。[渠道管理与策略](stage9-channel-outline.md)

### 模型与费率管理

系统管理员从 `/admin/models` 新建模型、上下架、维护定价分组及发布费率。运营人员可读模型、分组与费率版本。启用模型、启用分组和发布费率需要近期登录及变更原因。数据库校验管理员角色，变更与审计同一事务提交。应用角色不能直接写模型、分组或费率表。

对外模型代号、上下文上限和输出上限在新建时设置。新模型和分组默认关闭。先发布模型与分组的费率，再从渠道管理设置供应商模型 ID 和流式能力，完成绑定测试并启用渠道。最后启用分组并上架模型。上架前至少需要一个已启用分组和一条匹配已登记密钥的生效渠道。下架模型或停用分组会停止受理新请求，已受理的调用按原快照结算。

输入、缓存读取和输出分别按美元／百万 Token 定价，支持六位小数。分组倍率以 10,000 表示 1 倍，随该模型与分组的费率版本记录。发布时核对当前版本，在同一事务关闭旧费率并写入新版本，保留历史。兼容渠道采用不同输入价与缓存价前，须有生效渠道版本及对应绑定上可核对的缓存用量。流式渠道须同时从两种响应取得该数据。重新测试时可直接选择当前或上次生效版本。

环境配置中的费率需由渠道按组合接管后才能在后台调整。原有组合全部接管后，可增加新分组并定价。新组合完成绑定前不会出现在调用目录，种子数据不能覆盖后台接管后的费率。

## 9.4 用户管理

系统管理员从 `/admin/users` 按状态、邮箱前缀或用户 ID 分页查询，查看邮箱确认状态、后台角色、钱包余额、用量预占和退款冻结。运营人员按用户 ID 和状态查询，看到脱敏邮箱，可签发普通用户邀请。审计员和普通用户无此模块权限。补额沿用兑换码与钱包流水。

账号停用和恢复只改变 OpenToken 访问状态。停用阻止新登录、原有控制台会话和 API 密钥的新请求，已受理请求沿用原计费和结算流程。恢复后需要重新登录，原有且仍启用的 API 密钥可继续使用。Supabase 的封禁与软删除状态仍优先限制访问。账号保留原角色绑定，停用期间角色失效，也不计入有效管理员。

修改账号状态或后台角色需要近期登录和变更原因。拒绝自行变更及移除最后一位有效系统管理员。并发状态变更校验账号版本，角色变更校验原角色。状态或角色与审计同事务提交，审计记录操作者、目标、请求编号和变更内容。

邀请功能需在同一 Supabase 项目的服务端配置 `SUPABASE_SECRET_KEY`。后台只签发链接，由管理员或运营私下交给指定收件人。链接仅在首次签发成功时显示，账号通过既有的 `/invite` 设置密码后登录。系统先写邀请编号，再调用 Auth 并记录结果。重复提交不会再次调用 Auth 或显示链接。

外部结果未知时保留邀请编号，避免盲目重发。同项目的运维人员在两分钟后可执行 `pnpm db:admin reconcile-invite <邀请编号> <收件邮箱>`。命令校验编号与收件人，核对 Supabase Auth 是否已有该账号并记录审计。无账号时释放签发占用，可用新邀请编号重试。已有账号时保留占用，运维可按该账号的验证状态处理。已签发的链接不从 OpenToken 后台再次获取。

正式发布先运行迁移 012、013 和 `pnpm db:check`，再部署应用并核对 `/api/health`。开启后台邀请后，使用隔离账号验收链接、密码设置和首次登录。若需回退应用，目标版本须保留账号状态和会话版本校验，并重新验证停用或删除的账号无法登录或发起 API 新请求。

### 删除账号

系统管理员在用户列表选择「删除」，输入目标用户 ID 和原因，并通过近期登录校验。服务端核对账号状态和原后台角色，阻止自行删除和删除最后一位有效系统管理员。存在待完成结账或尚未终止的 Stripe 订阅时，先处理相应订单或订阅。

本地结账过期时，以 Stripe 结果为准。Stripe 沙盒运维可用 `pnpm db:stripe sync-expired-checkout <订单编号>` 核对。只有 Stripe 确认已过期且未支付，或在限定时间范围内查无匹配结账，才标记本地订单为已过期。已完成但尚未确认付款的结账继续等待 Webhook。

删除对 OpenToken 账号永久生效。账号状态、撤销后台角色、撤销 API 密钥和审计记录同事务提交。已受理的模型请求继续结算。Supabase 身份记录、钱包账本、订单和使用记录保留，系统管理员可通过「已删除」状态查看归档账号及钱包摘要。已删除账号无法使用停用、恢复或角色分配操作。

隔离验收覆盖了近期登录和目标确认、角色及账号版本冲突、并发删除只成功一次、审计失败整体回滚，以及失效会话、API 密钥和待入账兑换。删除前已受理的一笔模拟调用预占 2.00 美元，实扣 0.75，释放 1.25。归档钱包余额为 2.25 美元，预占归零，账本只记一笔扣费。构建通过，PGlite 与原生 PostgreSQL 17.12 环境各通过 63 项测试。

## 9.5 登录日志与操作日志
